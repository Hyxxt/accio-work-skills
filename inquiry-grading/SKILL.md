# 询盘分析与客户 ABCD 分级

## Purpose

把一段原始询盘（邮件 / 站内信 / WhatsApp 消息）转成结构化判断：
客户是谁、要什么、值不值得优先跟、下一步该做什么。
**分级由规则算，不由模型感觉算** —— 同样一封询盘，跑十次必须得到同一个等级。

## When to Use

出现以下情况时调用：

- 用户粘贴一条或一批询盘原文，要求分析/分级/排序
- 用户问「这条询盘值不值得跟」「哪个客户该先回」
- 用户要求生成询盘回复草稿或跟进计划
- 定时任务扫描新询盘并输出日报

## Inputs

从询盘原文或用户补充信息中提取，缺失就标「未知」，**不要猜**：

| 字段 | 说明 |
|---|---|
| inquiry_text | 询盘原文，必填 |
| buyer_company | 公司名，能从签名/邮箱域名推断则填，推断不出标未知 |
| buyer_country | 国家/地区 |
| product | 询价产品与规格 |
| quantity | 数量或 MOQ 意向，含单位 |
| target_price | 目标价，没有标未知 |
| certifications | 认证/合规要求（CE、FDA、RoHS 等） |
| buyer_type | 终端 / 贸易商 / 分销 / 电商卖家，能判断才填 |
| is_verified | 是否为平台认证买家（有则填，无则标未知） |

## Input Handling

按输入完整度分三档，**不要一律拒答，也不要缺字段就硬跑**：

### 一、有原文，但部分字段缺失

正常进入打分流程，缺失字段在输出里列入「未知字段」，该字段**不加分也不减分**。
不要因为信息不完整就把整条询盘判低——信息缺是客户的问题，不是询盘质量的问题。
但「下一步动作」里必须写清：追问哪几个字段可以让它升级等级。

### 二、只有结构化摘要，没有原文

照常分级，但在输出顶部加一行标注：`> 基于用户提供的摘要判断，未经原文核对`。

### 三、连询盘内容都没有

**拒答，不得推测。** 固定回复：

```
目前还缺少询盘原文，无法判断。
请提供以下任一项：
- 询盘原文（邮件 / 站内信 / WhatsApp 消息）
- 或包含以下字段的表格：产品、数量、客户国家、联系方式

收到后我会按「信号打分 → 等级映射 → 下一步动作」的流程处理。
```

## Workflow

1. **原文清洗**：去掉签名、免责声明、平台广告尾巴，只留业务内容。
2. **结构化提取**：按 Inputs 逐字段抽取。原文没有的字段一律标「未知」，禁止根据常识补全。
3. **垃圾询盘判别**：命中任一条直接判 D，不进入打分
   - 内容与主营产品完全无关
   - 只有「请发 catalog / price list」且无任何产品指向
   - 明显群发模板（同一段话术 + 无具体规格）
   - 索要免费样品且拒绝承担运费，同时无任何采购量信息
4. **规则打分**：按下方四级指标逐项打分，**只加不减**，满分 100。
5. **等级判定**：按分数区间映射 ABCD，同时记录触发器（哪个条件把它拉上去或压下来）。
6. **输出**：等级 + 分数 + 命中依据（引用原文原句）+ 下一步动作 + 回复要点。

## Grading Rules

### 硬信号（累计 55 分）

| 信号 | 分值 | 判定标准 |
|---|---|---|
| 明确数量 | 15 | 给出具体数字和单位；「需要很多」不算 |
| 明确规格 | 10 | 型号/材质/尺寸/功率等可执行参数 |
| 目标市场清晰 | 8 | 说明销售国家或终端场景 |
| 认证要求 | 7 | 提出具体认证标准 |
| 目标价 | 5 | 给出可对标的价格 |
| 采购周期 | 5 | 说明交货期或采购频次 |
| 平台认证买家 | 5 | 有 verified 标记 |

### 软信号（累计 25 分）

| 信号 | 分值 | 判定标准 |
|---|---|---|
| 公司可查 | 8 | 有公司名且官网/领英可定位 |
| 专业提问 | 7 | 问到工艺、包装、质保、模具费等非价格问题 |
| 沟通完整 | 5 | 有称呼、有落款、有明确回复方式 |
| 多轮历史 | 5 | 非首次接触，或历史有报价记录 |

### 减分项（最低 -20）

| 信号 | 分值 |
|---|---|
| 群发痕迹明显（无称呼、模板化） | -8 |
| 只问最低价、不谈规格 | -6 |
| 要求免费样品且不承担运费 | -4 |
| 联系方式残缺（无公司、无网站） | -2 |

### 等级映射

| 等级 | 分数 | 处置动作 |
|---|---|---|
| **A** | ≥ 70 | 2 小时内人工回复，销售主管同步知会 |
| **B** | 50–69 | 24 小时内回复，进入常规跟进序列 |
| **C** | 30–49 | 模板回复 + 补充提问，等客户补信息再升级 |
| **D** | < 30 或命中垃圾判别 | 不进跟进池，仅存档 |

### 一票否决（不看分数，直接压到 D）

- 索要与我方主营完全无关的产品
- 明显诈骗特征（要求先付「清关费」「代理费」、要求代收货款）
- 明确要求提供他人客户名单或报价单

## Output Language

**报告主体一律用中文输出**，因为这份报告是给中国运营团队看的，不是发给客户的。

- 等级、分数、命中依据、未知字段、下一步动作 → **中文**
- 引用询盘原文作为依据时 → 保留原文语言，用引号括起来，不要翻译（避免失真）
- 仅 `Reply Points` / 邮件草稿 → **英文**，因为要直接发给海外买家

**不要因为询盘原文是英文，就把整份报告改成英文。** 语言取决于读者是谁，不取决于输入是什么语言。

## Output Format

固定输出以下 Markdown 结构，不要加寒暄，不要加总结段落：

```
## 询盘分级结果

**等级：B（62 分）**
**客户：ABC Trading Co.（美国，贸易商，未认证）**

### 命中依据
- [+15] 明确数量：「need 5000 pcs monthly」
- [+10] 明确规格：「diameter 32mm, ABS material」
- [+8] 目标市场清晰：「for our US retail chain」
- [+8] 公司可查：官网 abctrading.com 可访问
- [-6] 只问最低价：原文「what is your best price」未提其他
- 未命中认证要求、目标价、采购周期（原文未提）

### 未知字段
采购周期、认证要求、是否终端

### 下一步动作
1. 24 小时内回复，先给阶梯价（5000/10000/20000）
2. 追问：认证要求、交货港口、是否需要 OEM 包装
3. 升级条件：客户回复中给出任一认证要求或明确交期 → 升至 A

### 回复要点（英文，3 句以内）
- 直接回应 5000 pcs 的阶梯价
- 用一句提问换取认证与交期信息
- 附一张规格确认表，不附完整目录
```

## Boundaries

- **不猜数量**：原文没有具体数字，一律标未知，不要写「预计采购量较大」
- **不美化等级**：分数不到 70 就是 B，不要因为「客户看起来很专业」上调
- **不编造公司信息**：无法查证的公司背景标「未核实」，不写推测
- **不下单不报价**：本 Skill 只做分级与建议，价格必须由人工确认后发出
- **一次一封**：批量询盘逐条输出，不要合并成一份总结
