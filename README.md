# Accio Work 自定义 Skill 实践：询盘分析与 ABCD 分级

阿里国际站询盘分级 Skill。基于 Anthropic Agent Skills 标准（Accio Work 与 Claude Code 通用），
在 Accio Work 上从零编写、两轮迭代、用真实询盘对照测试。

**仓库：https://github.com/Hyxxt/accio-work-skills**
直接下载 [`inquiry-grading.zip`](inquiry-grading.zip) 即可安装到 Accio Work。

## 为什么做这个

调研阿里国际站「AI 运营 / 智能体方向」岗位时，JD 要求「在 Accio Work 平台独立设计、开发、上线 Skill」，
并明确列出六个业务 Skill：询盘分析、客户背调、直通车广告诊断、Top20 商品矩阵诊断、品牌广告诊断、全店六维健康度诊断。

我先翻了平台技能库，搜索「客户」返回 16 个官方技能，覆盖竞品分析、客户声音、组织架构调研、RFM 分析等，
**但没有询盘分级这一类**。说明这六个 Skill 属于企业自身业务逻辑，需要从零写——而这正是该岗位的核心职责。

所以我的做法是：先照着平台上最接近的「客户 RFM 分析器」摸清结构，再按自己的判断重写一套分级规则。

## 设计要点：分级由规则算，不由模型感觉算

这是整个 Skill 的核心原则：**同一封询盘跑十次，必须得到同一个等级**。

模型只负责两件事：从原文抽取字段、按规则执行打分。
判断标准全部固定在文档里，包括权重、阈值、一票否决条件。
这与我在其他项目里的做法一致——算钱的、判合格的环节交给代码。

### 评分模型

| 层级 | 满分 | 包含信号 |
|---|---|---|
| 硬信号 | 55 | 明确数量 15、明确规格 10、目标市场 8、认证要求 7、目标价 5、采购周期 5、平台认证 5 |
| 软信号 | 25 | 公司可查 8、专业提问 7、沟通完整 5、多轮历史 5 |
| 减分项 | -20 | 群发痕迹 -8、只问最低价 -6、索免费样品 -4、联系方式残缺 -2 |
| 一票否决 | — | 无关产品、诈骗特征、索要他人客户名单 → 直接判 D |

等级映射：A ≥ 70（2 小时内回复）、B 50–69（24 小时内）、C 30–49（模板回复并追问）、D < 30（不进跟进池）。

## 两轮迭代记录

好 Skill 不是写出来的，是跑出来改出来的。这两次修改都是**实际运行后发现的问题**。

### v1.1：补输入缺失时的降级路径

**问题**：第一版只写了「不猜数量」，但没写「连询盘内容都没有时该怎么办」。
测一个官方 Skill 时发现，成熟的做法是：缺什么就明说缺什么、列出所需字段、绝不推测。

**修改**：新增 `Input Handling`，按完整度分三档——

- 有原文但字段缺失 → 正常打分，缺失字段不加不减，并在下一步动作里写明「追问哪些字段可以升级」
- 只有结构化摘要 → 照常分级，顶部标注「未经原文核对」
- 完全没有内容 → 拒答，用固定模板列出所需输入

关键判断写进了文档：**信息缺失是客户的问题，不是询盘质量的问题**，不能因为信息不全就把询盘判低。

### v1.2：锁定输出语言

**问题**：英文询盘进去，整份报告变成英文。但这份报告是给中国运营看的，不是发给客户的。

**修改**：新增 `Output Language`——报告主体中文、引用原文保留原语言不翻译、仅回复要点用英文。
文档里写死一句判断原则：**语言取决于读者是谁，不取决于输入是什么语言**。

## 测试结果

两条对照用例，验证「规则」和「兜底」两条路径都通。

### 用例 A：完整询盘 → 应走打分路径

输入特征：明确数量 5000 pcs、规格齐全（20W COB / IP65 / 5000mAh）、目标市场美国 120 家零售店、
CE + RoHS 认证、目标价 USD 12.50 FOB、35 天交期、公司名 + 官网 + 邮箱电话齐全。

输出：**A 级，70 分**，逐项列出依据——

| 信号 | 得分 | 依据（引用原文） |
|---|---|---|
| 明确数量 | +15 | Estimated quantity: 5,000 pcs for the first order |
| 明确规格 | +10 | 20W COB LED, 2000 lumens / IP65 / 5000mAh |
| 目标市场 | +8 | serving 120 retail stores across the southern US |
| 认证要求 | +7 | CE and RoHS certification |
| 目标价 | +5 | around USD 12.50 per unit FOB Shenzhen |
| 采购周期 | +5 | lead time within 35 days |
| 公司可查 | +8 | 公司名 + 官网 + 企业邮箱（标注本轮未核实有效性） |
| 专业提问 | +7 | 问 MOQ、包装、OEM 印刷 |
| 沟通完整 | +5 | 称呼、签名、职位、邮箱、电话齐全 |

未命中：平台认证买家、多轮历史（原文未提）

### 用例 B：垃圾询盘 → 应走一票否决

输入：`hello, please send me your catalog and best price list. we need many products. thanks`

输出：**D 级，0 分，hard D**（跳过打分直接否决），依据是只问目录不指产品、无数量、模板化措辞、无联系方式。

### 值得注意的行为

用例 A 的输出里出现了两句文档没有字面要求的话：
「官网实际有效性本轮未核实」「报价须经人工确认」。

对应 `Boundaries` 里的「不编造公司信息」和「不下单不报价」——
说明边界约束被正确理解并执行，而不是照抄条款。

## 怎么用

```
inquiry-grading/
  SKILL.md          核心说明书：元数据 + 流程 + 评分规则 + 输出格式 + 边界
```

1. 打包成 zip（根目录含 `inquiry-grading/SKILL.md`）
2. Accio Work → 插件 → 技能 → 右上角「上传」
3. 确认状态 Enabled，并在目标 Agent 的技能列表里勾选 Selected（**两处都要开才生效**）
4. 对话中直接描述任务即可自动触发，或输入 `/` 手动指定

## 与代码类项目的关联

Skill 是对 Agent 能力的封装，和我另外几个项目在做同一件事的不同层次：

- **理赔通**：Agent 自主调用条款检索与流程查询工具、最多六轮，工具调用过程可视化
- **RAG 知识库**：检索与引用留在代码侧，模型只基于给定片段回答，资料不足时拒答
- **本项目**：把业务判断标准写成规则，让 Agent 稳定执行，缺输入时明确降级

三者共同的取舍是：**把不确定的事留给模型，把要担责的事留给规则。**
